**Phase 3-C 着手前にご確認ください。**

```
東京エリア = WORLD 1
  1-1: さくらマンション新築A棟
  1-2: 桜ヶ丘リフォームB棟

```

**選択肢 2: 管理者が手動採番**
- 「これは WORLD 2 のステージ 3」と現場登録時に手動で番号を入れる
- 重要な現場をボスステージにできる

**選択肢 3: ハイブリッド**
- WORLD 番号は手動、STAGE 番号(同 WORLD 内の連番)は自動

▶ どの方式がお好みですか?

### 🔵 B. 従業員配置データの取得タイミング(優先度: 高)

「マップ上で誰が今どの現場にいるか」を表示する場合のデータソース:

**選択肢 1: 日報提出ベース(現状の実装方針)**
- 当日の日報が提出されると、その人が「その現場にいた」と判定
- 利点: 確定データ、追加入力不要
- 欠点: **日中はリアルタイムに分からない**(夕方以降にしか正確に分からない)

**選択肢 2: 朝のスケジュール予約ベース**
- 朝一番に「今日この現場行きます」と各従業員 or 管理者が予約
- 利点: **朝から「今日の配置」が一覧できる**
- 欠点: 入力の追加負担、変更時の更新漏れリスク

**選択肢 3: ハイブリッド(推奨)**
- 朝はスケジュール、夕方以降は日報で確定
- スケジュール画面と連動

▶ さくら株式会社様の実運用ではどれが現実的ですか?

## 5. リスク・前提条件

### 5-1. 現状特定されているリスク

| リスク | 影響 | 対応状況 |
|---|---|---|
| API キー入手の遅れ | Phase 7(外部連携)着手が遅延 | 早めに調整いただきたい |
| AI 機能の従業員受容度 | Phase 8 後半の導入可否 | 事前説明・同意取得フローを設計予定 |
| マスコット画像の著作権・商用利用範囲 | プロジェクト全体 | 秋元様ご提供素材の使用権を確認させてください |
| Supabase 無料枠の上限到達 | 本番運用開始時 | データ量が増えたら有料プランへ移行(月 ¥3,500 程度) |

### 5-2. 設計上の前提条件

- マネーフォワード本体は変更しない(API / CSV 連携のみ)
- 会計・給与は SAKURA OS 内で完結させない(マネーフォワードに必ず最終データを送る)
