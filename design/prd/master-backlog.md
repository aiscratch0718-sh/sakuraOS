## 実装順方針

「**実装効率順**」=「既存基盤の流用度 × 独立性 × 業務インパクト」で並べた結果:

1. **Tier 1**(全て)→ 基盤を埋める。本セッションで主要を着手。
2. **Tier 2**(順序: T2-01 勤怠 → T2-04 2FA → T2-02 図面 → 残り)→ 業務の骨格完成。
3. **Tier 3**(順序: T3-01 サクラコイン → T3-02 スケジュール → T3-03 ししまる → T3-04 ゲーム拡張)
4. **Tier 4**(必要に応じて随時、Tier 3 と並行可)

各 Tier 完了時に再度カバー率を測定し、本ファイルを更新する。

### 操作デバイスの方針(秋元)

- ⏳ メニュー振分は確定後に再検討(現時点では決定保留)
- ⚠️ 事務ロールは「総務課」だけでなく **施工管理課の事務** も存在 → 既存 `office` ロールの細分化または `org_departments` で吸収を検討
- ❌ リーダー・管理者の図面アップロードは **不要**

### DOC モジュール再定義(社長/秋元)— ★ 大変更
- ❌ **図面機能は丸ごと削除**(容量懸念 + 紙ベース運用)
- ❌ T2-02 図面アップロード → **削除予定**
- ✅ **「安全書類」を新設**:工事開始前に元請/協力会社へ提出する書類(Excel/PDF)+ 入構人員の資格・住所・連絡先
- ✅ **`projects` ↔ 安全書類** 紐付け:案件作成時の入力情報(元請、工期、入構人員)を安全書類のスタート情報として使用
- ✅ 案件作成時に **安全書類担当者へ通知** 自動発信(「作成必要案件あり」)

### 業務基本機能の紐付け(社長/秋元)
- ✅ `PROJ` ↔ `GENKA`(現場別原価管理)— 既に実装済み(`project_cost_aggregates`)
- ✅ `EST` ↔ `GAIKYO`(工事概況表) **新規仕様**:
  - 見積ステータスが「**受注済み**」になった時点で **工事概況表に自動反映**
  - 請求書発行で **「工事経歴書」を別途自動作成**(様式は概況表と異なる、建業許可書更新用)
- ❌ `GENKA` → `GAIKYO` の紐付けは **不要**(社長判断)

### 工事経歴書(新規)
- 表示項目: 元請名 / 工事名 / 案件責任者名 / **工期(和暦 年月日 開始〜終了)**
- トリガー: 請求書発行時に自動生成
- 用途: 建業許可書の更新

### 経費管理表(新規)
- 表示項目:
  - 見積金額(見積書ごと)
  - 仕入(材料)金額
  - リース金額
  - 協力会社(人工数 / 残業数 / 金額)
  - 諸経費
  - 車両交通費
  - 人件費(人工数 / 残業数 / 出張費)
  - 宿泊費(レオパレス / ホテル)

### USER マスタ拡張(社長/秋元)
- 既存:基本社員情報 + ロール + 時給
- 追加要件:
  - **健康診断の期日**
  - **職人スキル**(技能レベル、得意工種)
  - **人事評価データ**
  - **経験現場履歴**(履歴書のような形)
  - **個人情報**(全建情報、各種証明書類)
- → `profiles` を拡張、または `user_extended_profiles` で分離

### PROJ ↔ USER の紐付け(社長/秋元)
- 案件作成時、その工事に必要な **スキル・資格・経験年数** を指定
- 案件責任者が人員配置する際、**マスタ:USER の情報から要件を満たした人員が優先表示**(レコメンド機能)
- → 単価マスタ(QUAL)、資格マスタとの 3 者連動

### QUAL マスタ拡張(社長/秋元)
- 既存: 工種別の標準/下限/上限単価
- 追加要件:
  - **工事の松竹梅単価**(品質グレード別)
  - **役職別単価**(職長 / 一般 etc.)
  - USER の資格 + ORG の組織図(役職)から **単価を動的に決定** するロジック
- → `price_items` を拡張 + `position_rates` 中間テーブル

### ORG マスタ拡張(社長/秋元)
- **組織図の Excel インポート / エクスポート**(更新したらインポート)
- **公開フロー**: 社長が更新中は非公開 → 公開・登録した瞬間に **全社員へ通達**
- **役職履歴**: 各社員の所属・役職の履歴を持つ(例: 5月「一般」 → 翌5月「主任」)
- → `org_departments` `org_positions` `user_org_history` テーブル

### SEC マスタ(操作ログ)拡張(社長/秋元)
- 取得対象を **明示**:
  - 案件作成・更新
  - スケジュール登録
  - 工具管理(持出/返却)
  - 見積書・請求書の作成・更新・削除
- → 既存 `audit_log` で大半カバー済み。**請求書削除のログだけ抜けがあれば追加**

### REPORT3 拡張(社長/秋元)
- ✅ 既存: 3階層分類(大/中/小)+ 時間
- 🆕 **入力分類を 4 階層に拡張**(社長、`design/prd/feedback/2026-05-07_client-feedback.xlsx` の「項目」シートに途中案あり):
  - **特大分類**: 業界系統(冷凍冷蔵 / ケミカルプラント / 大型半導体 / 食品工場)
  - **大分類**: 工種(配管 / 鳶 / 保温 / 溶接 / 雑工事)
  - **中分類**: 大分類「配管」の場合のサンプル(冷媒 / 冷温水 / 冷却水 / 排水 / 食品プロセス / ケミカルプロセス / エネルギープロセス / 蒸気 / エアー)
  - **小分類**: 中分類「排水」の場合のサンプル(塩ビ/のり付け / 塩ビ/溶接 / 塩ビ/加工管・フランジ止め / SGPW/溶接 / SGPW/ネジ / SGPW/加工管・フランジ閉め / SUS / SGP_黒)
  - ※ あくまで途中段階。クライアントが残りの中分類・小分類を埋める前提。
  - DB 影響: `work_classifications` テーブルに `l0`(特大)を追加 → 4 階層対応 + UI ドロップダウンも 4 段階カスケードに変更
- 🆕 **その日の集計時間を決定 → 自動集計** → 経費管理表 / 各自評価へ反映
  - ⚠️ 夜勤の場合の除外ロジック要慎重設計(スケジュール事前入力ベース)

### 領収書提出機能 ★(秋元)
- ★3階層作業日報の入力時、**領収書提出も含める**
- フロー: スマホで撮影 → 精算有無 → カテゴリ選択(消耗品 / 食事代 等)→ 登録

- その後 **請求書 / 経費管理表へデータ連動**
- → `receipts` テーブル + Supabase Storage(`receipts` バケット)
